# Estado del proyecto Geelark-IA

**Actualizado:** 2026-10-09  
**Fase:** 0 — inicio desde cero y definición de requisitos  
**Implementación:** no hay módulos declarados como terminados o verificados en esta línea base.

## Acuerdo de inicio

El proyecto se desarrollará desde cero, paso a paso. No se importarán código, arquitectura, datos ni soluciones de proyectos o historiales anteriores. Las decisiones técnicas se tomarán en este proyecto y quedarán documentadas en GitHub.

## Principios acordados

1. Objetivo de costo operativo de 0 USD; evitar pagos obligatorios, tarjetas requeridas, pruebas temporales, cobros automáticos y APIs de pago.
2. Priorizar software libre, local o autoalojado y reducir la dependencia de proveedores.
3. Operación offline cuando sea técnicamente viable, documentando las limitaciones.
4. GeeLark será la referencia funcional para las características que se seleccionen; la equivalencia requiere pruebas.
5. Avanzar por tareas pequeñas, terminadas, probadas y documentadas.
6. Cada módulo tendrá manual de usuario completo y documentación técnica.
7. GitHub registrará requisitos, decisiones, tareas, problemas, soluciones, pruebas y cambios.
8. No afirmar que una función existe, que una prueba pasó o que una capacidad está garantizada sin evidencia.

## Alcance por definir

Antes de elegir tecnologías o desplegar infraestructura, confirmar con el usuario:
- Qué problema debe resolver primero el sistema.
- Qué funciones de GeeLark son prioritarias.
- Qué equipos y recursos están realmente disponibles.
- Qué versiones de Android se necesitan.
- Qué tipo de uso y capacidad se espera en la primera versión.
- Qué operaciones deben funcionar sin conexión.
- Qué condiciones de seguridad y acceso remoto se requieren.

## Decisiones técnicas pendientes

No están aprobados todavía el sistema operativo/hipervisor, el método de virtualización o emulación Android, la arquitectura distribuida, el stack, la base de datos ni la capacidad simultánea. No se desplegará infraestructura grande antes de una prueba mínima documentada.

## Registro

- 2026-10-09: se establece una línea base limpia para el trabajo futuro y se deja fuera el material de proyectos/historiales anteriores. Los requisitos de costo cero, trabajo incremental, documentación, trazabilidad GitHub, operación offline viable y comparación con GeeLark se conservan como reglas de trabajo.
